# Meta-Agent

A dynamic meta-agent system that decomposes any goal into a DAG of subtasks, runs specialized agents autonomously, and synthesizes the results into a coherent output.

Built with FastAPI + Google Gemini + Docker sandbox + Redis.

## How it works

```
POST /run "research quantum computing, simulate a circuit, write a blog post"
  │
  ▼
Planner (Gemini) → decomposes goal into DAG of subtasks
  │
  ▼
For each subtask → Agent (researcher / coder / writer / ...)
  │                     │
  │               ┌─────┴──────┐
  │               │  Tool      │ ← pre-built (web_search, code_executor)
  │               │  Registry  │ ← or dynamically generated by LLM
  │               └─────┬──────┘
  │                     ▼
  │               Docker Sandbox (--network none, 256m memory)
  │
  ▼
Evaluator → pass/fail per subtask (retry up to 3×)
  │
  ▼
Synthesizer → merges all outputs into final result
  │
  ▼
SSE "complete" event → client receives final output
```

### Key design decisions

- **NOMAD pattern** — agents share only what they need via Redis (statuses + summaries), each keeps its own LLM context
- **DAG scheduling** — independent subtasks run in parallel via `asyncio.gather`; dependencies block until ready
- **Dynamic tool generation** — if a subtask needs a capability no pre-built tool provides, the system generates one via LLM, tests it in Docker, and registers it at runtime
- **Sandboxed execution** — all code runs in Docker containers with `--network none`, 256m memory limit, 50-pid limit, and 30s timeout
- **No hardcoded agent roles** — the planner invents whatever roles the goal requires (researcher, data_analyzer, reviewer, etc.); system prompts are generated dynamically per subtask
- **Full pipeline logging** — every LLM call, tool result, and evaluation decision lands in `logs/{task_id}.log`

## Quick start

```bash
# Requirements: Python 3.12+, Docker, Redis

cp .env.example .env       # edit with your GEMINI_API_KEY
docker compose up -d       # start Redis
pip install -e ".[dev]"    # install dependencies

.venv/bin/python -m uvicorn src.main:app --reload
```

Send a goal:

```bash
curl -X POST http://localhost:8000/run \
  -H "Content-Type: application/json" \
  -d '{"goal": "explain quantum computing, write a simulation, and turn it into a blog post"}'

# → {"task_id": "abc12345"}
```

Stream results:

```bash
curl http://localhost:8000/tasks/abc12345/stream
# → SSE events: status → node → tool_call → tool_result → complete
```

Check status:

```bash
curl http://localhost:8000/tasks/abc12345
# → {"task_id": "...", "goal": "...", "status": "done", "result": "..."}
```

## Run with Docker

```bash
docker compose up --build
```

- App: http://localhost:8000 (dashboard at `/` or `/dashboard`)
- Redis runs as a sidecar container (healthchecked; the app waits for it)
- `GEMINI_API_KEY` is read from `.env` via `env_file`
- The app container mounts the host Docker socket (`:ro`) — the sandbox builds images and runs code through the **host** daemon. The socket mount is root-equivalent on the host
- Sandbox scripts are passed via the `meta-agent-sandbox-tmp` named volume (`SANDBOX_MOUNT` env); per-task logs land in the `logs-data` volume at `/app/logs`
- uvicorn runs as a single non-root worker — the SSE event bus is in-memory, so the app must not be scaled

Stop with `docker compose down` (add `-v` to also drop the volumes).

## Stack

| Component | Choice |
|-----------|--------|
| LLM | Google Gemini (`gemini-3.1-flash-lite`) via `langchain-google-genai` |
| API | FastAPI (async, SSE streaming) |
| Sandbox | Docker containers |
| Shared state | Redis (statuses, summaries, trace log) |
| Tests | pytest (`asyncio_mode = auto`) |

## Sandbox

The Docker sandbox image (`meta-agent-sandbox`) includes:
- `numpy`, `pandas`, `scipy`, `sympy` — scientific computing
- `qiskit` — quantum computing SDK

Code execution is isolated per run:
- `--network none` — no internet access
- `--memory 256m` — memory capped
- `--pids-limit 50` — fork bomb protection
- 30s timeout per execution

The image auto-builds on first use.

## API

| Method | Path | Description |
|--------|------|-------------|
| `POST` | `/run` | Submit a goal → returns `task_id` (202) |
| `GET` | `/tasks/{id}` | Get task status + result |
| `GET` | `/tasks/{id}/stream` | SSE stream of pipeline events |
| `GET` | `/` or `/dashboard` | Web dashboard |

### SSE events

| Event | Payload |
|-------|---------|
| `status` | `running` / `done` / `failed` |
| `node` | Pipeline stage (planner / spawner / executor / evaluator / complete) |
| `subtask` | Agent status (running / done / retrying) |
| `tool_call` | Tool name + arguments |
| `tool_result` | Tool name + result |
| `error` | Error message |
| `complete` | Final result |

## Project structure

```
src/
├── main.py                      # FastAPI entrypoint, .env loader
├── config.py                    # Environment variables
├── task_logger.py               # Per-task pipeline logger
├── api/routes.py                # REST + SSE endpoints
├── agents/base.py               # Agent run loop (LLM + tools)
├── factory/
│   ├── agent_factory.py         # Creates agents, resolves/generates tools
│   └── prompt_builder.py        # Dynamically builds system prompts
├── meta_agent/
│   ├── planner.py               # Gemini → DAG of subtasks
│   ├── orchestrator.py          # Core pipeline: schedule, retry, synthesize
│   ├── evaluator.py             # Subtask output validation
│   └── synthesizer.py           # Merges all outputs into final result
├── tools/
│   ├── __init__.py              # Tool + ToolRegistry definitions
│   ├── registry.py              # Tool lookup
│   ├── sandbox.py               # Docker sandbox executor
│   ├── generator.py             # LLM generates + tests tools in sandbox
│   ├── composer.py              # Chains tools into pipelines
│   └── prebuilt/
│       ├── web_search.py        # Wikipedia search
│       ├── file_reader.py       # Read local files
│       └── code_executor.py     # Execute Python in Docker sandbox
├── event_bus/bus.py             # In-memory SSE event bus
├── shared_state/redis_store.py  # Redis persistence
├── types/
│   ├── agent_spec.py            # AgentSpec dataclass
│   └── task.py                  # Subtask + Task dataclasses
└── web/dashboard.html           # Minimal web UI

config/agents.yaml               # Optional base system prompts
docker/sandbox.Dockerfile        # Sandbox container image
tests/                           # pytest suite (108 tests, 6 integration skipped)
```

## Configuration

| Env var | Default | Description |
|---------|---------|-------------|
| `GEMINI_API_KEY` | — | Google Gemini API key |
| `GEMINI_MODEL` | `gemini-3.1-flash-lite` | LLM model |
| `REDIS_URL` | `redis://localhost:6379/0` | Redis connection |
| `MAX_TOOL_CALLS` | `10` | Max tool rounds per agent |
| `MAX_RETRIES` | `3` | Max retries per subtask |
| `RETRY_DELAY` | `1.0` | Seconds between retries |
| `LLM_TIMEOUT` | `60.0` | LLM request timeout |
| `TOOL_CALL_DELAY` | `1.0` | Seconds between tool calls |
| `SANDBOX_TIMEOUT` | `30` | Seconds per sandbox execution |
| `TOOL_GEN_RETRIES` | `3` | Retries for tool generation |
